## 1. Executive summary

T4C was extended from a recon-only EASM console into a **three-stage chain**:

```
recon  →  exploit  →  objectives
 (discover)  (breach)   (collect produce)
```

The chain is not three copies of the same app. Organizations are **discovered once in recon** and shared; a first-class `Stage` / `Mode` value threads through tasks, findings, assets, monitors, schedules, scopes and the UI; and each stage ships its **own SDK registry** with a hard minimum of 8 plugins (delivered: 13 recon / 10 exploit / 10 objectives). A governance action advances an organization one link at a time. The console exposes a three-icon mode toggle and dedicated stage-prefixed screens, with a shell console and an export drawer for the post-exploitation stages.

Everything is opt-in where it matters: recon broadening stays **off by default** (`TaskOptions.Broaden` / `PolicyConfig.Broaden`), and existing timeouts, zombie reaping, auth gating and soft-delete behaviour are preserved.

## 2. The chain model

### 2.1 Stages and mode

`internal/domain/stage.go` defines:

| Value | Meaning | Next |
| --- | --- | --- |
| `recon` | Attack-surface discovery (the original EASM surface) | `exploit` |
| `exploit` | Validation and breach of discovered assets | `objectives` |
| `objectives` | Post-exploitation collection of "produce" | terminal |

Helpers: `Valid()`, `Next()`, `String()`, `StageForCategory()`, `StageForTaskKind()`, `AllStages`.

### 2.2 Threading `Stage` through the model

The `Stage` column was added to `Task`, `Finding`, `Asset`, `Monitor`, `Schedule`, `Scope` and `SubmitInput`. `Engine.Submit` resolves the stage from the request when valid and otherwise derives it from the task kind. Legacy rows with an empty `stage` column are treated as **recon-owned** by `stagePredicate()` in `internal/store/stage.go`, so no historical data disappears.

### 2.3 Asset classification

`AssetKind` was broadened to `bucket`, `api_endpoint`, `credential`, `password`, `session`, `certificate`, `file`, `site`, `url`, `cidr` and the derived `exploited` state. `Asset.Confidence`, `Asset.Exploited` and `Asset.ExploitedAt` were added. Exploit/objectives asset views are driven by `exploited = true` rather than by duplicating assets per stage.

### 2.4 Governance

`POST /api/v1/organizations/{id}/advance-stage` (`requireWrite`) validates the sequential `recon → exploit → objectives` transition, records an audit event, and is surfaced in the org-detail `StageBanner` and the stage Organizations screen.

## 4. Backend achievements

### 4.1 Domain model and stores

- `internal/domain/exploit.go`: `ExploitTaskOptions`, `ExploitResult`, `ShellSession`, `ShellCommand`, `Artifact`.
- `internal/domain/objective.go`: `ObjectiveKind` (`shell`, `download`, `probe`, `loot`, `flag`), `Objective`, `ObjectiveAction`.
- `internal/store/exploit.go`: `CreateExploitTask`, `MarkAssetExploited`, `OpenSession`, `CloseSession`, `ReigniteSession`, `AppendShellCommand`, `CreateArtifact`, `ListArtifacts`, `GetArtifact`, `ListExploitedAssets`, `ListShellCommands`.
- `internal/store/objective.go`: `CreateObjective`, `GetObjective`, `ListObjectives`, `UpdateObjectiveStatus`, `AddObjectiveAction`, `ListObjectiveActions`.
- `internal/store/tasks.go`: `ListTasksByStage`.
- `internal/store/stage.go`: stage-scoped list queries, `ChainCounts`, `ChainKindCounts`, `ChainOrgCounts`.
- `internal/store/produce.go` (T10): `ProduceSummary` — server-computed objectives/artifact analytics using grouped SQL, soft-delete aware and optionally org-scoped.

### 4.2 SDK registries — the ≥8-per-stage hard requirement

| Stage | Count | SDKs |
| --- | --- | --- |
| Recon | **13** | `dnsx`, `subfinder`, `naabu`, `httpx`, `tlsx`, `nuclei`, `poc`, `ct-logs`, `asn`, `dnszone`, `cloud`, `rdns`, `endpoints` |
| Exploit | **10** | `sqli`, `ssrf`, `lfi`, `api_exploit`, `rce`, `web_shell`, `credential_access`, `session_hijack`, `brute`, `deserialization` |
| Objectives | **10** | `shell_session`, `file_exfil`, `screenshot`, `packet_capture`, `data_export`, `lateral_move`, `persistence`, `internal_recon`, `artifact_collect`, `credential_harvest` |

Registries live in `internal/modules/exploit/` and `internal/modules/objective/` with `Register`, `Registry`, `Find`, `PluginsByType` and `Counts`. Contract tests (`internal/httpapi/chain_sdk_test.go`, `internal/modules/exploit/registry_test.go`, `internal/modules/objective/registry_test.go`) enforce the minimum, metadata completeness, idempotent registration, session-requirement declarations and **registry isolation** (no recon SDK leaks into the exploit registry).

### 4.3 Tasking engine and queue topology

New task kinds: `exploit`, `exploit_brute`, `exploit_inject`, `objective`. New steps: `exploit`, `postex`, `probe`, plus the opt-in `broaden` step. `StepPlan`, `executeStep` and `queueForStep` were extended:

| Step | Queue |
| --- | --- |
| `broaden` (opt-in) | `q.discovery.broaden` |
| `exploit` | `q.exploit.http` |
| `postex` | `q.exploit.postex` |
| `probe` | `q.objectives.probe` |

`MergePolicy` ORs `PolicyConfig.Broaden` into `TaskOptions.Broaden`; the flag defaults to `false`. Exploit steps flip `Asset.Exploited`, open `ShellSession`s, create `Objective`s and write `Artifact`s; objective steps run the objective SDK plugins.

### 4.4 REST API and OpenAPI

`internal/httpapi/server.go` registers the protected chain routes; `internal/httpapi/chain_api.go` and `internal/httpapi/stage_api.go` implement them.

**Generic stage-scoped routes** (`/{stage}` validated by `parseStage`):

```
GET|POST /{stage}/tasks
GET      /{stage}/overview
GET      /{stage}/organizations
GET      /{stage}/assets
GET      /{stage}/findings
GET|POST /{stage}/monitors
GET|POST /{stage}/schedules
GET|POST /{stage}/policies
GET|POST /{stage}/groups
```

**Exploit stage:**

```
GET  /exploit/sessions, /exploit/sessions/{id}
POST /exploit/sessions/{id}/close, /reignite, /commands
GET  /exploit/sessions/{id}/commands
GET  /exploit/assets
GET  /exploit/plugins
```

**Objectives stage:**

```
GET    /objectives/list, /objectives/summary, /objectives/{id}
PATCH  /objectives/{id}/status
GET|POST /objectives/{id}/actions
GET    /objectives/artifacts/list, /artifacts/{id}, /artifacts/{id}/download
DELETE /objectives/artifacts/{id}, /objectives/{id}
GET    /objectives/plugins/list
```

`internal/httpapi/openapi.json` documents **102 paths**, every operation has a unique `operationId` and responses, and `TestOpenAPICoversEveryAPIRoute` / `TestOpenAPIOperationsHaveUniqueIDsAndResponses` enforce this contract on every test run.

### 4.5 Governance, lifecycle and security

- `AdvanceStage` is write-gated and audit-logged; transitions are strictly sequential.
- `GET /objectives/artifacts/{id}/download` is auth-gated, writes a sanitized `Content-Disposition` (`safeDownloadName`), returns a JSON envelope with checksum/storage path, and records `chain.artifact_download`. Artifacts are never served from the SPA static path.
- `artifact` and `objective` were added to `lifecycleResourceOrder`, so soft-deleted produce is **recoverable** from Administration → Recycle Bin. Deletes record `chain.artifact_delete` / `chain.objective_delete`.
- `ShellCommand` and `ObjectiveAction` writes are audit-logged; status/action endpoints are `requireWrite`-gated.
- Session re-ignition reuses recorded non-secret connection metadata only.

### 4.6 Produce summary (T10 backend capability)

`GET /objectives/summary` returns a `ProduceSummary` with totals (`objectives`, `exported`, `artifacts`, `totalBytes`, `checksummed`) and distributions (`byStatus`, `byKind`, `bySeverity`, `artifactsByKind`), computed with grouped SQL rather than loading rows into memory. Optional `organizationId` scopes the aggregation. Deleted produce is excluded through `active()`. Postgres integration tests (`internal/store/produce_integration_test.go`) assert totals, distributions, org scoping and soft-delete exclusion.

### 5.4 Typed API layer

`web/src/api/chain.ts` is a typed wrapper over `openapi-fetch` using `execute()` for CSRF/401/error handling. It defines explicit domain types (`ShellSession`, `Objective`, `Artifact`, `StageOverview`, `ProduceSummary`, …) because the generated OpenAPI schemas predate the `Stage`/`Exploited` columns. Generated types in `web/src/api/schema.d.ts` are regenerated from `openapi.json` via `pnpm generate:api`. All chain methods are exported through the shared `api` object.

## 6. Guardrails honoured

- **English-only** code, comments, commits and docs.
- **Opt-in broadening**: `TaskOptions.Broaden` / `PolicyConfig.Broaden` default `false`; a dedicated `broaden` step and queue are only scheduled when enabled.
- **No regressions**: the previously shipped fixes (timeouts/reaper, org mapping, skeletons, clickable rows, icon tabs, real PoC severity, risk distribution, map pins, selectable policies) remain intact; the final `pnpm lint`, `typecheck`, `build` and `test` runs are all green.
- **Per-step/per-task timeouts and zombie reaping** are respected by the new steps.
- **Auth gating**: sessions and artifacts are never exposed through the static SPA path; writes are `requireWrite`-gated and audit-logged.
- **No asset duplication** across stages; exploit is a derived `exploited` state.

## 7. Capabilities added beyond the plan

Useful, working additions that were not strictly required by the blueprint:

1. **`GET /objectives/summary`** — server-computed produce analytics (grouped SQL, soft-delete aware, org-scoped) rendered as server-authoritative charts on the objectives Overview.
2. **`ObjectiveWorkflow`** — full objective lifecycle (status transitions + operator action logging + live timeline) with role gating mirroring the backend.
3. **`ProduceBreakdown`** — distributions by status/kind/severity, export coverage, extracted byte volume and checksum coverage.
4. **Recycle Bin recoverability** for artifacts and objectives (T9), with audit events.
5. **SDK contract tests** enforcing the ≥8 minimum, metadata completeness, idempotency and registry isolation for every stage.
6. **Console-wide lint/prettier hardening** — `pnpm lint` now passes cleanly (two unused-variable errors fixed; `LoadingBlock` now exposes its label to assistive technology).
7. **Stage-scoped automation parity** for monitors/schedules/policies/groups, including create endpoints.
